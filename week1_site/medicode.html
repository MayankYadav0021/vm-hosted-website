Observed RAG Cases

  • Relevant retrieval: appointment, patient registration, and authentication questions retrieved their expected MediCore source documents.
  • Out-of-scope: a Delhi weather question retrieved unrelated project documents, demonstrating why scope control is required.
  • Insufficient information: a 2024 revenue question retrieved semantically related documents, but no source contained the requested revenue information.

RAG vs No-RAG

The same three MediCore questions were compared with and without retrieved project context. Without RAG, no MediCore sources are supplied to the generation stage. With RAG, the top-4 retrieved sources provide project-specific context.

Model Evaluation Lab

MediCode supports evaluation of Qwen 2.5 Coder 3B, StarCoder2 3B, and CodeLlama 7B using a common evaluation framework. The project retains previously completed model-comparison results and separates them from the newer MediCore retrieval and codebase experiments.

The evaluation framework covers explanation, code retrieval, dependency understanding, bug analysis, code generation, refactoring, and RAG-based questions.

Full new 28-question LLM generation evaluation was not rerun on this CPU-constrained VM after RAG generation tests exceeded practical execution limits. No new LLM accuracy figures are fabricated here.

System Scope

MediCode is a technical developer assistant. It uses retrieval-augmented generation to retrieve relevant software documentation before generating an answer.
